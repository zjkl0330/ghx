# ghx 守则速查

> `RULES.md` 是完整版（含每条的历史原因），这份是**执行清单**：动代码前扫一遍，交付前对一遍。
> 两者冲突时以 `RULES.md` 为准。视觉规范见 [`STYLE.md`](./STYLE.md)。

---

## 零、十条红线

违反任何一条都算返工，没有例外。

1. **只做安卓 APK**，不做 Web 版。浏览器预览只是验证手段。
2. **不引入后端**、不做账号体系、不加遥测。需要 `client_secret` / webhook / FCM 的功能一律标「需后端」不做。
3. **不擅自 commit / push**。做完只报告改动与未提交状态，等用户发话。
4. **不 force push、不重写历史、不推用户没要求的远端分支。**
5. 破坏性操作（删令牌、删仓库、公开转私有、批量改可见度、删分支）**必须二次确认**。
6. 新增纯逻辑**必须有单测**，总数只增不减。
7. 颜色**只用 `theme.css` 的 CSS 变量**，组件里不写死色值。
8. 令牌**一律 AES-256-GCM 加密落盘**，明文只在请求瞬间存在于内存。
9. **不许手拼加速站前缀**，一律走 `mirrors.ts`（地址分两种风格，手拼必有一种 404）。
10. **不许把没验证的事说成已验证**。没在真机跑过的，就写「没在真机验过」。

## 二、界面与交互

- 基调 **GitHub Primer**，深色默认，浅色是**等价配色**（不是反色）。
- 默认「跟随系统」；手动指定后立即生效并记住。
- 首屏配色由 `index.html` 内联脚本决定，**不许先闪一帧深色再跳浅色**。
- 状态栏颜色随主题走（`@capacitor/status-bar`）。
- 底栏入口可配置：仓库 / 星标 / 热门 / 流水线，**默认前三个**，至少保留一个；流水线默认收起。
- **令牌与设置不是页签**：点头像进「我的」，保险库 / 设置 / 审计 / 检查更新都在这一层。
- 二级页面（个人页 / 设置 / 令牌 / 审计 / 流水线）各算一层，返回逐层弹出。
- 列表行给足点击热区；文案最多两行，超出用省略号。
- 新增页面 **必须同步改 `backnav.ts` 并补测试**。

---

## 三、令牌与解锁

- 默认**免密**：打开即用，不设口令、不弹解锁页。加密 ≠ 每次拦人。
- 「启动验证」是可选：口令只用来包裹设备密钥，可开、可改、可关；**忘了无法找回**。
- 旧版口令派生密钥的库要能一次性迁移，令牌解密后重加密，原文不变。
- 「锁定保险库」清空内存密钥与明文，并收起所有弹层。

## 四、返回键（顺序固定）

| 当前状态 | 按返回 |
|---|---|
| 软键盘弹着 | 先收键盘 |
| 口令面板 | 关面板，留在设置页 |
| 发行版 / 复刻 | 回仓库详情 |
| 运行详情 | 回工作流详情 |
| 其他弹层 | 关最上面一层 |
| 审计日志 | 回设置 |
| 批量多选 | 退出多选，保留筛选 |
| 非首页页签 | 回仓库页 |
| 仓库页 | 第一次只提示，2 秒内再按才退 |

批量改可见度执行中，返回要被拦下（与界面禁用取消按钮一致）。网页按 Esc 走同一套层级。

## 五、缓存

| 路径 | TTL |
|---|---|
| 搜索 | 5 min（配额最贵） |
| `/user/repos`、星标列表 | 60 s |
| 运行列表 | 15 s |
| 作业详情 | 20 s |
| 发行版 / 复刻 | 2 min |

- 写操作成功后按前缀失效，**不许「改完还看到旧值」**；新增写接口必须同时扩 `invalidationPrefixes()`。
- **刷新与轮询必须传 `fresh: true`**，否则一直命中旧数据。
- 缓存跟着 `GitHubClient` 实例走，换令牌即换缓存。

## 六、翻译

- 通道顺序 `auto`：**Edge → Azure（有密钥）→ MyMemory → Google**。
- 必须按**通道字节上限**切分后再发；MyMemory 单次 450 字节，整段发会被拒、长段落静悄悄留在英文（历史 bug，不许回退）。
- 判断要不要翻用 `needsTranslation()`，不能只看 `hasChinese()`。
- 链接与行内格式用 ⟦⟧ 占位保活；**不要用数字序号**（会被中文化）。
- 仓库自带中文版优先于机翻。
- 名字不翻（`isNameLike()`）：纯字母、无空格、camelCase / 带数字下划线 / 拼音可切分。
- 续翻游标用**块下标**，不能用「第几个待翻段」。

---

## 七、版本与发布

- **patch +1，满 10 进 minor**（0.4.9 → 0.5.0）。版本号只维护 `package.json` 一处。
- `versionCode` = `major*10000 + minor*100 + patch`；当前 1.2.0 → `10200`。
- **每次改动都发 Release**，不攒版本。
- Release 正文取自 **tag 注解**，要写成人能读的变更说明。
- **默认预发布**；要正式版，在注解里写 `<!-- release: stable -->`。
- 下载地址一律经 `mirrors.ts`，不许在界面里拼前缀。
- 构建产物三查：版本号、签名指纹、包内是否真含新代码。

## 八、工程纪律

- 纯逻辑抽成纯函数并配单测：版本比较、状态映射、耗时、分组排序、缓存失效、返回决策。
- 提交前必跑：`npx tsc -b`、`npx vitest run`、`pnpm build`。**任一失败不提交。**
  - 类型检查必须 `tsc -b`，`tsc --noEmit` 对 project references 是空跑。
- 提交信息写**为什么**，不只写改了什么。
- 已知问题如实写进提交说明或 tag 注解，不用「应该没问题」糊过去。

## 九、验证标准

一次合格交付至少包含：

| # | 验证 | 当前基线 |
|---|---|---|
| 1 | 单元测试 | **1523** 条 / 69 文件 |
| 2 | 浏览器实测 390×844 @2x | `scripts/verify-*.py`，34 个 |
| 3 | 真实接口 | 关键功能用真令牌打一次，不能只靠 mock |
| 4 | 产物校验 | `apksigner` 指纹 = `fd6a8ea4…`、包内版本号正确 |
| 5 | 先证伪再下结论 | 报「全绿」前先确认覆盖到位 |

浏览器验证**必须有头**（`xvfb-run`）：headless 不渲染 `backdrop-filter`，玻璃会被拍成色板。

## 十、不许承诺的事（已知边界）

- **热门不是官方 trending**：GitHub 没有开放该 API，本项目是 `search/repositories` 取「近期创建 + star 达标」再按日均重排。不假装是官方榜单。
- **搜索结果不返回「我是否 star 过」**。
- **令牌无法在 App 内创建**：GitHub 无公开创建端点。
- **加速站本质是 302**，链路通不通取决于当地网络；测速只反映当下。
- **免密钥翻译没有 SLA**：Edge 接口随时可能下线，必须有降级链。
- **归档 / 可见度需要 admin 权限**，看他人仓库时不显示入口。
- **没有模拟器 / adb**：通知外观、WakeLock、前台服务、安装器，一律只有静态 + JVM 证据。

## 十一、协作方式

- 中文沟通，**结论先行**，先给结果再说过程。
- 能自己判断的直接做，不反复回问；路径有分歧时选最贴近真实环境的那个。
- **不擅自扩大范围**，不把没做的事说成做了。
- 每次交付说清三件事：**做了什么 / 验证到什么程度 / 还有什么边界**。
- 先侦察再动手：不猜、不靠记忆，改之前先读真文件、打真接口。
